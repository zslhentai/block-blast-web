继续使用现有 TypeScript + Canvas 2D + Vite 架构，保留规则、发牌、存档、拖拽投影和移动端输入保护。下一阶段优先调整蓝色背景、棋盘凹槽、方块斜面和 HUD 布局，再补消除与 Combo 表现。当前 8×8 棋盘和三个固定手牌槽已经适合这一方向，无须更换引擎或重写玩法。

### 棋盘与立体方块

棋盘按“外框亮边 → 暗内沿 → 深色底板 → 64 个轻圆角凹槽”绘制。空格不采用纯线网；内侧暗边与微弱亮面形成压入感，外框圆角明显大于单格圆角。

方块按“右下投影 → 深色底座 → 四条斜面 → 中央块面 → 顶部细亮边”绘制。上边最亮、左边次亮、右边偏暗、底边最深；斜面初始可取单格边长约 12%–16%，再并排校准。主体近方形，避免把斜面块做成高圆角软糖。所有色系采用同一光源方向，托盘按比例缩小，不能仍用平面小方块。

本轮基于同步后的 HTML、CSS 和 TypeScript 源码核对当前表现，未启动网页做新的运行截图；环境没有项目 `node_modules`，也未安装 Bun 或依赖。因此下列属于源码可确定的差距，不声称完成逐像素网页对比或真机测试。

| 项目 | 当前实现证据 | 与原图的差距 / 下一阶段方向 |
| --- | --- | --- |
| 背景 | [`canvas.ts`](../../src/renderer/canvas.ts) 的 `clearCanvas` 和 [`style.css`](../../src/style.css) 均用 `#1a1a2e` | 改为协调的蓝色渐变；Canvas 不应盖住 CSS 背景产生分界 |

## 6. 分阶段优化方案（仅方案，本轮未实现）

### P0：主题、布局与静态材质

1. 在 renderer 内增加主题对象和共享 `drawBlock`，由现有 `drawCell`、`drawPiece` 调用。主题包含背景、空格、外框、各色块面/斜面/阴影，颜色编号继续来自原状态；不改 `src/logic`、规则版本或存档结构。
2. 保留 `calculateLayout` 为唯一棋盘/托盘几何来源，补外框内边距与小屏约束。输入投影、合法落点和绘图必须使用同一组 `gridOffset/cellSize`；不能在绘图时额外平移棋盘却不更新输入坐标。
3. 用 DOM/CSS 调整分数和最高分层级，装饰性皇冠/齿轮可用自绘 SVG；保留原按钮语义、可访问名称、`data-testid`、焦点样式和至少 44 CSS px 触控区域。中文和高分位数要留足宽度。
4. 使用 Canvas 2D 路径和渐变生成材质，不将六张含整屏界面与广告的 PNG 用作运行时贴图。静态棋盘可按尺寸/DPR 缓存，方块可按主题/颜色/尺寸缓存，先测量再决定缓存范围，无需新引擎或生产依赖。

验收先看空盘与混色中盘。背景一致、棋盘是完整正方形、块面斜面方向统一，托盘和拖拽块使用同一材质；指针落点没有视觉偏移。

### P1：设置与消除/Combo 反馈

1. 在现有 `<dialog>` 上实现蓝色面板、暗遮罩、清楚的分隔行和开关样式。保留音效、减少动画、规则和许可内容，不新增无对应能力的按钮。
2. 扩展现有 `flash` 为短命表现状态，记录清除格、清除前颜色和效果起止时间；数据来自一次有效落子的前后状态与现有 `checkAndClearLines`。逻辑立即提交并保存，特效只读取快照；不要通过 `setTimeout` 延后更新棋盘。
3. 层次采用：棋盘/已落块 → 消线预览或清除覆盖 → 托盘/拖拽块 → 局部 Combo。效果位置受棋盘边界约束，DOM 提示使用 `pointer-events: none`，避免新增输入遮挡。
4. 普通消线使用稀疏方点、暖色细光带；Combo 使用浅青文字厚蓝描边和少量黄绿纸屑。仍以项目现有 `combo` 状态解释连击；多线奖励和连击概念不能因原图字样混为一条新规则。
5. 原图无法给出时长。可先试用清除约 180–240ms、Combo 约 600–900ms 作为网页调参起点，明确这不是测得的原版数据。减少动画时取消粒子、光带移动和缩放，保留静态文字或短颜色提示。

动画统一走现有按需 `requestAnimationFrame`。快速连续落子时给旧效果明确的替换/合并策略，暂停、重开、resize、销毁时清理，避免旧局特效闪回或无人游玩仍持续绘制。

### P2：性能与竖屏验证

缓存静态棋盘、减少反复创建渐变和昂贵的大面积 `shadowBlur`；初始为粒子设上限（例如普通消线 24、Combo 48，属建议值），实际以手机测量调整。只在拖拽或效果活动期间连续绘制；不改变已有 CSS 像素输入与 DPR backing store 的分工。

绘制加层和主题化后，再运行项目既有 Bun 类型检查、单测、交互测试与构建。本轮没有游戏实现变更，不添加镜像实现的测试，也不为了文档/图片移动安装依赖运行整套游戏测试。

## 7. iPhone / 安卓竖屏适配与验证计划

### 约束

- 保留 `viewport-fit=cover`、四侧 safe-area 和动态视口策略。截图的整屏留白包含应用/广告空间，网页不复制广告区，也不硬编码原图底部留白；多余空间用弹性间距吸收。
- 棋盘边长由可用宽度和“可用高度减去 HUD、托盘、安全间距”共同约束。窄屏缩小棋盘，短屏先收缩装饰留白，不能压扁棋盘或让手牌掉到屏外。
- HUD 用 CSS 像素布局，Canvas backing store 按 DPR；事件转换继续使用现有 `toLocal`，不要再次把指针坐标乘 DPR。
- iPhone Safari 地址栏展开/收起、旋转、后台恢复，以及安卓 Chrome 的工具栏变化均可能触发尺寸改变。沿用取消当前拖拽、重算布局策略；本次手势不能因重排误落子。
- 设置弹窗在短屏需要内部滚动，关闭控件始终可到达；显示弹窗时棋盘保持原位，关闭后恢复此前游戏状态，不把暂停误当新局。
